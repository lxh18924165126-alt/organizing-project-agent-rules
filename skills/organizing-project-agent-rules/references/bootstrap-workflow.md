# Bootstrap 工作流

根 `AGENTS.md` 缺失是合法输入。完整读取统一 `policy-spec.md`、根模板、叶子模板和账本模板后执行本流程。

## 调查与证据

1. 盘点根和子目录的规范/异常命名 `AGENTS.md`、override、其他助手说明、README/CONTRIBUTING/架构文档。
2. 检查 manifest、锁文件、构建、测试、lint、类型检查、CI、部署、基础设施、schema/migration、生成配置、公共 API/共享类型和 workspace 结构。
3. 其他助手说明只作证据。证据优先级：用户明确信息 > 现有项目规则 > 机器强制配置 > 多源代码结构 > 单一代码模式。
4. 单一代码模式只记低置信度候选，不写成硬规则。多个独立来源相互印证且无冲突时才可标为 `inferred-high-confidence`。

## 集中提问门

调查完成后，仅当未知项无法从仓库可靠获取、会实质改变根禁止事项/架构护栏/路由、且省略会导致编造政策时，集中提问一次。已回答问题不再询问；非关键未知项保守省略。不得写 TODO、占位符或猜测。

## 输出

- 创建根 `AGENTS.md` 和当前领域实际需要的 `docs/agent/` 叶子。
- 前端、后端、契约、数据库、安全、基础设施均须有实际仓库信号才创建；不创建空文件。
- 根只引用真实文件；默认不创建嵌套 `AGENTS.md`。已有局部规则须保留、迁移或等价合并并进入账本。
- 使用统一预算、风险、路由、冲突优先级、可选工作流和验证器。
- 根必须写入精简的 Superpower default-deny policy；bootstrap 不得根据复杂度、R1/R2、计划、多 Agent、TDD、调试或验证状态创建额外授权门。
